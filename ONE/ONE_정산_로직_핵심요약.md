# ONE 정산 로직 핵심 요약

이 문서는 현재 코드 기준의 핵심 정산 흐름만 정리한 것이다.

## 1. 적용 범위

- 대상 회사: `새회사`
- 대상 화주사: `ONE`
- 다른 회사나 컬리형 정산 로직과 섞지 않는다.
- 데이터 기준은 업로드된 ONE 엑셀의 RAW 데이터다.

## 2. 엑셀 업로드 처리

엑셀은 다음 순서로 읽는다.

1. RAW 시트 찾기
   - 우선 시트명 `RAW`, `로우`를 찾는다.
   - 없으면 첫 번째 non-empty 시트를 RAW로 본다.
2. 생수 시트 찾기
   - 우선 시트명 `생수RAW`, `생수`를 찾는다.
   - 없으면 두 번째 non-empty 시트를 생수로 본다.
3. 헤더는 고정 행이 아니라 상단 20행에서 자동 탐색한다.
4. 컬럼명은 약간 달라도 alias로 읽는다.
   - 예: `배송 일자` -> `일자`
   - 예: `주문 번호` -> `주문번호`
   - 예: `송장 번호` -> `운송장번호`
   - 예: `배송원명`, `기사명` -> `SM`
   - 예: `상품명` -> `품목명`

같은 파일 내용은 `raw_hash`로 중복 업로드를 막는다.

## 3. RAW 행 묶기

RAW 행은 바로 1건으로 정산하지 않고 주문 그룹으로 묶는다.

묶는 기준:

```text
일자 + 수수료명칭 + SM + 주문번호
```

결과:

- 같은 그룹 1개 = 1가구 또는 1착지
- 같은 그룹 안의 RAW 행 수 = 박스 수
- 추가박스 = `박스 수 - 1`

주문번호가 비어 있으면 최근 행의 패턴이나 운송장번호를 이용해 보정한다.

## 4. 웨이브와 항목 분류

`수수료명칭` 텍스트로 웨이브와 항목을 분류한다.

우선순위:

1. `당일` 또는 `일요` 이면서 `N3` 포함
   - `N3_당일`
2. `1W` 또는 `2W` 포함
   - `W1,2_당일`
3. `당일` 또는 `일요`
   - 기본적으로 `W1,2_당일`
4. `새벽`
   - `W4_새벽`

항목 분류:

- `SSG` 포함 -> `SSG`
- `공동` 또는 `공동배송` 포함 -> `공동배송`
- `트레이더`, `애플` 포함 -> `트레이더스`
- `YES24`, `도서` 포함 -> `YES24`

분류가 안 되면 업로드 이력에 `UNMAPPED_FEE_NAME`으로 남고 검토 필요 상태가 된다.

## 5. 단가 계산

지급명세서와 배송원 목록의 지급액은 RAW의 원본 금액이 아니라 현재 단가표 계산값 기준이다.

### W1,2 SSG

- 박스 수 기준 테이블 사용
- 6박스 이상은 5박스 단가 + 초과 박스당 400원

### N3 SSG

- 박스 수 기준 테이블 사용
- 6박스 이상은 5박스 단가 + 초과 박스당 400원

### W4 SSG / W4 공동배송

- 박스 수 기준 테이블 사용
- 6박스 이상은 5박스 단가 + 초과 박스당 200원

### YES24

- W1,2 / N3: 박스당 1,430원
- W4: 박스당 2,475원

### W1,2 공동배송

- 해당 일자의 W1,2 공동배송 + 트레이더스 착지 수를 기준으로 구간 단가를 정한다.
- 금액 = `구간 단가 * 박스 수`

### W1,2 트레이더스

- 해당 일자의 W1,2 공동배송 + 트레이더스 착지 수를 기준으로 구간 단가를 정한다.
- 금액 = `구간 단가 + 추가박스 * 1,000원`


## 6 생수 처리

생수 시트는 정산 주문으로 묶지 않고 수기 항목으로 들어간다.

- 생수 1행 = 200원
- 기사명 기준으로 해당 기사 지급명세서에 `생수` 항목으로 합산된다.
- 저장 위치는 `OneDriverStatementOverride.manual_items`
- source 값은 `one_water_raw`

생수 시트에 날짜와 기사명에 해당하는 컬럼이 없으면 생수 항목 없이 RAW만 처리한다.

## 7. 상계 건 / 운송료 외 항목

명세서 상단에서 입력하는 상계 건은 수기 항목으로 저장된다.

입력 단위:

- 운송장번호
- 사유
- 금액
- 상품명

저장 후 명세서에는 `사고귀책 상계건`으로 합산되어 표시된다.

명세서 총액:

```text
단가표 기반 운송료 합계 + 생수 + 상계 건 + 기타 수기 항목
```

## 9. 화면별 숫자 기준

### 월별 요약

- 월 전체 배송 수량과 정산 금액을 서비스/항목/일자/기사 기준으로 집계한다.
- 대시보드 표는 원본 파일의 검은 대시보드 양식과 맞추기 위해 source 금액도 함께 보관한다.

### 배송원 목록

- 기사별 지급액은 지급명세서 합계 기준이다.
- 즉 `단가표 기반 계산액 + manual_items 합계`다.

### 배송원별 정산

- 기사별 지급명세서를 만든다.
- 상단 지급내역은 단가표 기반 계산값이다.
- 하단/우측에는 생수와 상계 건 같은 운송료 외 항목이 반영된다.

## 10. 삭제와 재계산

업로드 이력을 삭제하면:

1. 해당 업로드의 RAW 주문 데이터가 삭제된다.
2. 해당 월의 자동 생수 수기 항목을 다시 만든다.
3. 월별 캐시를 지운다.
4. 화면은 다음 조회 시 다시 계산된다.

업로드 후에도 월 단위 재계산이 한 번 실행된다.

## 11. 가장 중요한 구분

현재 시스템에는 금액 기준이 두 가지 있다.

### 원본 금액

- RAW 파일에 들어 있던 금액
- `source_amount`, `source_row_amounts`로 보관
- 원본 검은 대시보드 표 검증에 사용

### 지급명세서 금액

- 현재 단가표로 다시 계산한 금액
- 배송원 목록, 배송원별 정산, 지급명세서 합계에 사용

두 금액이 다를 수 있다.
지급명세서가 맞는 기준이면 배송원 목록도 지급명세서 금액을 따라야 한다.
